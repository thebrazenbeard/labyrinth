## Immutable design

Implementation: `labyrinth/minotaur_prospective_study.py`; schema
`labyrinth.minotaur-prospective-public-neural-study.v1`. The canonical JSON
protocol SHA-256 is
`b37ac57d4f93fc4148b2bee5d18d6efb3dcb0d52646796cf35ae1142d69217ba`.
The 100-row predeclared seed manifest SHA-256 is
`664737a816fca6f8afeecb04051b3a0d692a0141b5fe127b6912f5e77d467c58`.
Hash identity alone is not a trusted timestamp or execution attestation; the
reviewed source commit containing this protocol must predate full outcomes.
The full runner requires a separately retained SHA-256 digest of its canonical
source manifest (the study module, neural-rule module, and offline CLI
byte hashes). It compares that expectation
before fitting and verifies that source and frozen protocol remain unchanged
after the hundredth pair. The expectation must come from the reviewed
revision, not be accepted from an untrusted changed runtime.
The source-manifest digest at this protocol freeze is
`1f4b54d1b0d228e74f7ce6afd45d1b79da69ba779d39b585c5248677b8f0a732`.

Exactly 100 **matched pairs** are generated by index (not a grid or optional
sample). Four separately domain-separated SHA-256 seed streams give dataset,
initialization, program, and corruption seeds. Published development seeds
are excluded. Collisions are resolved deterministically; the manifest is
frozen and no failed seed is replaced. Both trained arms start from identical
12 float64 CPU coefficient values, receive exactly the same 36 supervised
examples (12 per operation), use the same optimizer policy and are evaluated
on exactly the same program suite for that pair.

- Bilinear representation: `[1, x/8, y/8, xy/64]` per operation.
- No-cross-term representation: `[1, x/8, y/8, x²/64]` per operation.
- Three operation selectors and modulo-97 projection are supplied priors.
- Optimizer: PyTorch strong-Wolfe L-BFGS, learning rate 1.0,
  `max_iter=500`, soft `max_eval=500`, **hard closure budget 500**.
  A request for closure 501 aborts that arm and restores its original
  coefficients. `require_fit=False`: poor supervised fits remain evaluated,
  not filtered out or retrained.
- Controls: unchanged bilinear initialization (zero updates), and a bilinear
  head trained on deterministically deranged labels within each operation
  using the same optimizer policy. If corruption cannot be constructed or
  fails, record failure and make the pair a non-win; no substitute controls.

The 500 budget was chosen after prior *development* work showed that 200
iterations were inadequate for a known difficult seed. This policy is not
blinded to that development history. L-BFGS arms may consume different actual
numbers of closure calls despite identical limits; record observed counts.

## Precommitted evaluation and statistical rule

Each seed pair has 128 unique, six-step, free-running register programs from
its separately derived program seed. Both arms receive the same programs.
The generator discards any program with a gold transition where both operands
are at most 8, so every gold atomic transition lies outside the whole
training-eligible small/small domain. That restriction introduces a known
evaluation distribution shift; it is applied without inspecting model errors.
Exact-program correctness requires **every intermediate model state** to
equal its independently recomputed gold state. No teacher-state correction.

The **single primary event** for seed pair *i* is:

`10 * (bilinear_exact_programs_i - no_xy_exact_programs_i) > 128`.

In integer counts this requires at least **13 more exact programs** for the
bilinear arm, i.e. strictly more than 10 percentage points. Missing or failed
trained arm, frozen control, corrupt-label control, invalid evaluation,
or rank/optimizer error is a **non-win**, included in the fixed
denominator of 100. Nonfit but successfully scored models remain included.
Do not stop, rescue, tune, add pairs, or choose an advantageous checkpoint on
the basis of these evaluations. A systemic source/provenance breach invalidates
the study instead of yielding a success claim.

Primary null: `P(pair_win) <= 0.5` under the *specified deterministic seed
generator as an operational sampling model*. One-sided exact binomial
`p = sum(comb(100,k) for k in range(wins,101)) / 2**100`; reject at nominal
`alpha=0.05` only for **59 or more** wins (58 gives ~0.0666053; 59 gives
~0.0443130). The pseudo-random seed stream and common arithmetic domain limit
the real-world independence interpretation of this p-value. The result speaks
to majority-of-seeds material representation benefit, not mean gain, universal
competence, intelligence, or an independent private examination.

Secondary **descriptive only**: exhaustive 28,191-atom accuracy after
excluding exact training keys, by-operation and wrap subsets; exact program
and intermediate-state counts for each arm, frozen/corrupted control metrics,
design ranks, fit flags, closure counts and model coefficient digests.
Program executions and atomic items are **not independent inferential
replicates**. No secondary significance claim or optimizer-method comparison.

## Source and custody limitations

The public arithmetic functions, representation, development seeds, and
heldout task family have already been inspected. This is a prospective
**seed-replication** experiment, not genuinely untouched task material.
Do not infer either private generalization or neural discovery of
multiplication: the bilinear arm is explicitly given `xy` as an input feature.
The study reports source-file hashes, dependency version and deterministic
config/seed/data/program hashes for local reproduction; these can be
fabricated by a hostile producer and do not prove independent execution.

Full execution consumes exactly 100 reserved pairs and yields only a
`public_primary_gate` of `PASS`/`FAIL` on the predeclared public hypothesis.
Partial execution on reserved pairs is **not supported**: a separate
`--development-smoke` CLI mode uses previously exposed development seeds
47, 19, 808, and 59, returning `INCOMPLETE` and no inferential p-value.
Run from a clean reviewed revision, with pinned CPU PyTorch 2.5.1+cpu,
one thread and deterministic algorithms enabled. The CLI requires an
explicit external `--expect-source-manifest-sha256` for the full run and
writes its output file exclusively. Every report retains `qualification=NOT_ESTABLISHED`,
`graduation_authority=none`, `minotaur_graduated=false`, `deployed=false`.
Private evaluator questions, independently held signing/custody secrets,
durable attempt accounting, external rollback anchor and protected installation
remain distinct gates, none exercised here.
