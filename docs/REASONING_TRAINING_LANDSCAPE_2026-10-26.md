## Verdict

Labyrinth should become a **model-agnostic suite of procedurally generated, independently verifiable environments plus controlled training experiments**. The *ascension* should mean calibrated progress to novel tasks and more difficult *structures*, not escalating persuasive prose, self-ratings, or reward-model approval. Its strongest possible future claim is measured *transfer*, not a model saying it has become smarter.

## Failure modes to design against from day one

> **Hostile challenge — reward hacking:** A system can maximize the metric without improving the intended ability. See [formal reward gaming](https://proceedings.neurips.cc/paper_files/paper/2022/hash/3d719fee332caa23d5038b8a90e81796-Abstract-Conference.html). Fail any run whose reward improves while an independent checker finds invalid actions, leaked answer keys, or unchanged task success.

> **Hostile challenge — apparent generalization:** Agents can overfit large sets of procedural levels. [CoinRun](https://proceedings.mlr.press/v97/cobbe19a.html) demonstrated why separate train/test instances matter; the additional Labyrinth risk is shared **generating structures** across seeds. Hold out operation compositions, task families, lengths, alternative surface renderings, and an independent suite—not merely pseudorandom numbers.

> **Hostile challenge — beautiful explanations:** [ICML 2026 experiments](https://proceedings.mlr.press/v306/yu26av.html) show that reward-optimized task accuracy need not imply faithful or causally influential reasoning traces. Prefer executable intermediate state/action witnesses and counterfactual intervention tests. Don't request private chain-of-thought or grade ornate rationales as correctness.

> **Hostile challenge — contaminated benchmarks:** [ACL contamination taxonomy](https://aclanthology.org/2023.findings-emnlp.722/) and [RL experiment-design analysis](https://jmlr.org/papers/v25/23-0183.html) reinforce precommitted unseen test splits, independent training seeds, matched budgets, uncertainty estimates, and all-run reporting. Once a final split affects selection, it is development data and must be replaced.

Other concrete traps: all-correct/all-wrong GRPO groups give little ranking signal; curriculum difficulty selected on test results leaks selection; LLM judges exhibit preference biases; “trained” outputs that are simply cached demonstrations are context adaptation; changing one deterministic hash doesn't prove a valid training history; CPU/GPU installations may differ from package names. Historical benchmark archives can be valuable reproducibility data but cannot be used as a fair same-condition comparison without matching the generating protocol.

> **Hostile source inspection — false structural sample size:** The current `program_maze.py` uses exactly **four hard-coded training instruction structures and four hard-coded holdout instruction structures**, despite sampling different numbers and seeds. Therefore hundreds of instances from one split are not hundreds of independent *reasoning structures*. Even a positive LoRA effect is restricted to these finite public templates. Report accuracy by structural fingerprint; expand to parameterized grammars, held-out compositional rules and an independently authored blind family before claiming general structural transfer.

## Proposed environment protocol (future iteration)

The current `maze.py` / `program_maze.py` produce question-answer instances and exact scoring. Incrementally generalize to an interface whose contracts can also represent interactive mazes:

1. `Generator(seed, family, difficulty, split) -> Instance`: public observation, bounded legal action schema, hidden evaluator-only solution/witness, semantic/structural fingerprint, generator-version hash and difficulty parameters.
2. `Environment.step(instance, state, action) -> (next_state, terminal, error)`: deterministic, sandboxed, no host commands or external API calls from model text. Have at least one *independent* implementation or oracle for each accepted challenge family.
3. `Verifier(episode) -> Outcome`: binary correctness primary; separately report path legality, efficiency, formatting and optional shaped reward. Verifier-only answers never enter prompt, feedback history intended for final testing, or model-controlled files.
4. `Adapter.generate(observation, sampling_config)`: local inference endpoint, HF inference, replay, or constrained external model; **does not mean trainable**.
5. `Trainer.fit(train_only, base, config) -> immutable checkpoint/receipt`: separate optional plugin for HF/PEFT SFT first, later DPO/GRPO. Report model/tokenizer hashes, update counts, consumed examples, optimizer, peak RAM/VRAM, train loss, seeds, artifacts, and exact runtime.
6. `Evaluator.compare(arms, sealed_splits)`: frozen base, genuine candidate, equal-exposure sham/no-update, corrupted supervision, prompt-only comparator and optional uniform-vs-curriculum arm, with strict equal prompt/token/step policy, fresh-process reload and paired uncertainty.

**Do not conflate levels:** a public logic riddle with `ANSWER: N` is a single-step *task*, not yet an environment with state transitions; claiming “interactive maze RL” requires a real `step` loop and validated trajectory replay. Keep the current functioning CLI until the replacement passes parity tests.

### Recommended staged gate — a proposal, not completed training

1. **Isolated dry-run:** Verify local model metadata/tokenizer, memory headroom, reproducible loading, offline mode, and permitted dependencies. Choose a small already-local HF-format checkpoint if available; otherwise seek an explicit model selection and model-download decision. The existing SmolLM3-3B weights are a candidate for *read-only qualification*, not guaranteed to be the economical first learner.
2. **Real SFT/LoRA proof on the target:** In an isolated environment, attempt a strictly bounded supervised update with an initially solvable generator family, record CPU/GPU peak usage and wall time, save adapter separately, reload fresh, and run frozen baseline/trained/zero-update/corrupt-label arms on train-disjoint examples. If the CUDA toolchain remains unavailable, a CPU-only tiny experiment is acceptable if practical; don't silently train in a service/another machine.
3. **Transfer falsification:** Hold out operation compositions, longer programs, changed renderings and a task family not used during adaptation. Add multiple independent training seeds and negative-transfer monitoring. Only after a reproducible benefit passes these should curriculum learning and RL be considered. Preserve a single untouched final set and preregister the primary effect threshold.
4. **Downstream integration last:** Export a versioned adapter and evaluation receipt for separately governed local-model systems. No import into a live assistant runtime or auto-activation without qualified local effects and the owner's explicit authority.
